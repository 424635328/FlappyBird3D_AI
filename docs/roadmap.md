# 路线图

按"改动成本 / 可观察收益"排序的候选方向。每条都标注了落点，避免只停留在想法。

## A. 训练范式

| 方向 | 一句话描述 | 落点 | 成本 |
| --- | --- | --- | --- |
| 多智能体对抗 | 引入 `PipeAdversaryAgent` 控制下一组管道的高度/缝隙，与小鸟零和博弈 | 新增 Agent + `Behavior Parameters` + 双行为配置 | 高 |
| 合作双鸟 | 两只小鸟共享生命与得分，需要同时穿过相邻管道 | 场景多 Agent + 共享奖励 | 中 |
| 竞速模式 | 多只小鸟同场，按排名给奖励 | 多 Agent + 排名奖励 | 中 |
| 模仿学习 | 录制人工演示，用 BC / GAIL 预热策略 | `DemonstrationRecorder` + 配置 `behavioral_cloning` | 中 |
| 内在奖励 | 加入 curiosity / RND 鼓励探索 | 配置 `reward_signals.curiosity` | 低 |
| 课程学习 | 先大缝隙慢速，再逐步收紧 | 配置 `environment_parameters` + 场景侧读取 | 中 |

## B. 智能体能力

| 方向 | 一句话描述 | 落点 | 成本 |
| --- | --- | --- | --- |
| 连续跳跃力度 | 动作从离散 3 分支改为 1 维连续，学习"跳多高" | `OnActionReceived` + 动作空间类型 | 中 |
| 多动作组合 | 冲刺、滑翔、急降各自成独立分支 | 动作分支数组 + 物理参数 | 中 |
| 视觉输入 | 用相机像素替代手工向量观测（CNN） | `CameraSensorComponent` + `vis_encode_type` | 高 |
| 能量系统 | 每次振翅消耗能量，通过特定区域补充 | 新增能量状态 + 观测与奖励改造 | 中 |

## C. 环境动态性

| 方向 | 一句话描述 | 落点 | 成本 |
| --- | --- | --- | --- |
| 移动/旋转管道 | 管道上下浮动或绕 Z 轴旋转，窗口动态变化 | `PipeMovement` 扩展 + 观测增加速度/角度 | 中 |
| 动态障碍 | 场景中出现额外飞行物或坠落方块 | 新预制体 + 标签 + 观测 | 中 |
| 风场/重力区 | 按区域施加水平风或改变重力 | 触发器区域 + `Rigidbody` 施力 | 低 |
| 目标收集 | 管道间散布金币，奖励以收集为主 | 生成器 + 触发判定 + 观测 | 中 |

## D. 工程与性能

| 方向 | 一句话描述 | 落点 | 成本 |
| --- | --- | --- | --- |
| 管道对象池 | 复用管道实例，避免频繁 `Instantiate/Destroy` | `PipeSpawner` 内部池 | 低 |
| 管道注册表 | 用列表替代每步 `FindGameObjectsWithTag` | `PipeSpawner` 暴露只读列表，`FlappyAgent` 直接读 | 低 |
| 观测归一化 | 对速度、距离显式缩放，便于迁移与复用 | `CollectObservations` | 低 |
| 多元回归测试 | 为观测维度、奖励符号、场景构建列表加自动化断言 | `Assets/Tests/`（Unity Test Framework） | 中 |
| CI 扩充 | 在现有"仓库规范"之外，增加 C# 编译与 EditMode 测试 | `.github/workflows/` | 中 |

## 优先级建议

1. **管道注册表 + 对象池**：低风险、直接影响训练吞吐，且不改变行为语义。
2. **观测归一化 + 单元测试**：为后续更换观测/动作提供安全网。
3. **课程学习**：不改代码结构，只加配置与场景读取，收益直观。
4. **多智能体对抗**：改动面最大，建议在前三项稳定后再动。
